# Mobile app (Android + iOS)

`apps/mobile` is a native React Native app built with Expo SDK 58 and expo-router. It is **not** a WebView wrapper: screens are native components; the routing engine, data access, validation, translations and design tokens are the same TypeScript packages the web app uses.

**Verification status:** type-checks (`tsc`) and produces an Android Hermes bundle with `expo export` (also checked in CI). It has **not** been run on a physical device or simulator in this environment — do that before release.

## Features

- Search, building/floor/room screens, native SVG floor map (pan, pinch-zoom, tap rooms)
- Navigation with step-by-step directions, floor switching, accessible routing, arrival state
- Camera QR scanning (`expo-camera`), permission requested on tap only; manual code entry when denied
- Deep links: `campusnav://q/<token>`; Android App Links / iOS Universal Links for `https://<CAMPUSNAV_LINK_HOST>/q/<token>` when configured
- Offline: campus bundle cached in AsyncStorage; cached data clearly labelled with its date
- Lecture reminders: OS-level local notifications for the next 7 days (works offline, no server)
- Push infrastructure: `getPushToken()` + `push_tokens` table; sending requires a server job (see below)
- English / Kurdish Sorani / Arabic with RTL layout (direction applied per component, no app restart), Noto Sans Arabic bundled for Sorani glyph coverage
- Permissions: camera only. Location, microphone and storage are not requested (location/mic explicitly blocked on Android).

## Run in development

```bash
pnpm install
cp apps/mobile/.env.example apps/mobile/.env   # optional; empty = demo data
pnpm dev:mobile                                 # Expo dev server
```

Open with **Expo Go** (supports camera and local notifications) or build a development client:

```bash
cd apps/mobile
npx expo run:android      # requires Android SDK
npx expo run:ios          # requires macOS + Xcode
```

## Production builds with EAS

```bash
npm i -g eas-cli
cd apps/mobile
eas login
eas init                       # creates the EAS project; put the id in EAS_PROJECT_ID
eas build --platform android --profile preview      # installable APK for testing
eas build --platform all --profile production       # store builds
eas submit --platform android|ios                   # store upload
```

Before store submission (placeholders in `app.config.ts`):

- `ios.bundleIdentifier` / `android.package` (`com.nulltech.campusnav`) — confirm ownership
- `CAMPUSNAV_LINK_HOST` and host the association files on the student web domain:
  - `/.well-known/assetlinks.json` (Android, with the release signing certificate SHA-256)
  - `/.well-known/apple-app-site-association` (iOS, with team id + bundle id)
- Store listings, screenshots, privacy policy URL, data-safety/privacy labels (camera only; no tracking)
- App icon and splash are generated by `pnpm icons` into `apps/mobile/assets/`

## Push notifications for schedule changes

Local reminders work without any server. Remote pushes (e.g. "your lecture moved to room 210") need:

1. `EAS_PROJECT_ID` set and an APNs key / FCM credentials uploaded via `eas credentials`.
2. Signed-in users storing their Expo push token in `public.push_tokens` (RLS: owner only).
3. A server-side sender (Supabase Edge Function triggered by a database webhook on `schedule_changes`) that finds affected users and calls the Expo Push API. This sender is **not implemented yet** (see ROADMAP).

## Offline behaviour

- First launch needs connectivity (or demo mode) to download the campus bundle.
- After that, maps, rooms, lecturers and the cached timetable work offline; routing is computed on-device.
- Live changes (schedule changes, announcements) are only as fresh as the last successful sync; the UI shows the sync date whenever cached data is displayed.
